# Security Lens

Look only for ways the change can be abused.

* Untrusted input reaching SQL, a shell, a path, a template, a deserializer or a URL fetch.
* Missing or weakened authentication and authorization checks.
* Secrets, tokens or personal data in code, logs or error messages.
* New dependencies, new network calls, new file writes outside the project.

Evidence is the input an attacker sends and what it reaches.
